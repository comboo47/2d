武器 / 子弹 / 技能 — 属性盘点

为「基础属性 / 动态属性」框架设计准备 · 字段已逐文件一手核对（Godot 4.6）· 2026-06-14

🆔 标识元数据 🔗 资源引用 / 资源管理 🔢 数值参数 🎛️ 类型 / 行为开关 ⏱️ Runtime 动态状态

前四类来自配置（Definition 的 @export，编辑器可填）；Runtime 动态状态是运行时才产生、会随玩法变化的值（节点 / Flow 实例 / Manager 持有）。耦合 标记跨系统引用或重复存储。

四、系统耦合 / 重复点

① 武器数值「双存」（重复存储）

base_speed / base_damage / max_energy / energy_cost / energy_regen / max_charge_speed / charge_rate / min_fire_interval

WeaponDefinition（配置）— on_start 拷贝 → WeaponFireFlowBase 实例的 _xxx（运行时副本）

同一数值存两份。运行时只改副本、不回写、当前也不随 buff 变。「基础属性=配置那份模板，动态属性=运行时可变副本」正是要在此引入引用关系、消除盲拷。

② 子弹 base_damage / damagebuffid「双重身份」

BulletBase 里它们是 @export（场景可手填）同时 apply_definition() 又用 BulletDefinition 的值覆盖。

基础值有两个来源（场景默认 vs 定义），易混淆。统一时需明确「定义优先、@export 仅作无定义时回退」。

③ 技能「配置与状态同类」（最大结构不一致）

SkillBase（Resource）同时装 @export 配置 和 cooldown / skill_owner / is_active 运行时状态，靠 SkillRegistry.get_skill() 返回 duplicate(true) 副本隔离实例。

武器/子弹是「Definition 配置类 + Base/Flow 运行时类」两段式；技能是一段式。做统一基础/动态框架时，这是三类里最需要拉齐的差异。

④ 跨系统引用链（正常依赖，非缺陷）

Weapon —bullet_def→ Bullet ｜ Weapon —skill_slot→ Skill ｜ Weapon —fire_flow→ Flow

Skill —flow_refs→ Flow ｜ Bullet 命中 → BattleManager → 触发武器 Skill(ON_HIT/ON_KILL)
